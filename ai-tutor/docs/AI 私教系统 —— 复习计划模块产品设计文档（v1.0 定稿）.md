1. 业务约束与核心原则
1.1 底层算法约束
改良 SM-2 间隔重复：每个知识点独立状态，无批量统一排期
双层隔离核心：
DB 层（全局正式复习 normal_review）：决定长期遗忘曲线、next_review_time、毕业/掌握、复习债
前端会话层（本组即时纠错重试）：仅作用于当前复习会话；重试阶段完全前端内存运算，不请求后端、不上报日志、不修改数据库任何字段
1.2 核心规则
作答分类隔离：
normal_review：卡片首次作答，调用后端接口，参与完整 SM-2 算法计算
session_retry：本组内重试阶段，仅前端内存队列处理，无任何后端交互
复习组临时性：复习组为前端内存临时对象，不持久化；中途退出，未作答单词全部退回全局待复习池
放行规则：首次作答选「模糊」/「不认识」，均进入本组重试队列，无循环次数上限；本组内必须选「认识」才可放行出组
复习债机制：全局待复习池不会自动过期清空，未复习任务持续累积，产生复习债
复习与学习解耦：复习与学习新内容/生成测验互不阻塞，用户可自由切换
2. 数据模型关键字段（知识点复习状态）
interface ChunkReviewState {
  chunk_id: string              // 知识点唯一标识
  ease_factor: number           // SM-2 记忆系数 (初始 2.5，范围 1.3~3.0)
  correct_streak: number        // 连续正式答对计数，毕业/掌握判断依据
  next_review_time: DateTime    // 下一次全局正式复习时间，数据库权威值
  last_normal_answer: 'mastered' | 'vague' | 'forgotten'  // 上一次正式作答结果
  is_mastered: boolean          // 是否已掌握/毕业，移出待复习池
  review_count: number          // 总复习次数
  last_review_time: DateTime    // 最近一次复习时间（含会话重试）
}
⚠️ 重要：组内重试阶段所有用户操作，不会修改以上任意字段。数据库状态仅在 normal_review 首次作答时更新。

4. 核心交互规则（关键变更点）
4.1 统一答案解析展示
主队列/重试队列无差别：用户作答后，立即展示答案与解析（当前逻辑不变）
解析后再决策：用户阅读解析后，再次选择按钮
统一「不认识」处理：
主队列：选「不认识」→ normal_review=forgotten（SM2大幅降级+入重试队列）
重试队列：解析后选「不认识」→ 同主队列「遗忘」逻辑（SM2降级+压入重试队列尾部）
主/重试队列在页面上保持一致，用户感知为同一组复习
4.2 3 级语义化按钮（前端）↔ 5 级数据（后端）
前端展示（3 级）	语义	后端映射（5 级）	SM-2 quality
不认识	完全不会/彻底忘记	forgotten	0
模糊	有印象但说不清/不确定	vague	3
认识	清楚掌握，能准确说出	mastered	5
后端仍存 5 级（0/3/5），预留未来扩展回 5 级按钮的空间。

5.3 后端分支逻辑
用户选择	SM-2 处理	DB 更新	返回标记
认识	正向：提升 ease_factor，correct_streak +1，计算新 next_review_time，满足毕业条件置 is_mastered=true	全量更新	need_session_retry: false
模糊	小幅降级：小幅降低 ease_factor，小幅缩短 next_review_time	更新 ease_factor、next_review_time、last_normal_answer='vague'	need_session_retry: true, retry_reason: "vague"
不认识	大幅降级：大幅降低 ease_factor，correct_streak=0，生成很近的 next_review_time	全量更新，correct_streak=0	need_session_retry: true, retry_reason: "forgotten"
6. 前端内存侧逻辑（复习组会话）
6.1 复习组内存结构
interface ReviewBatch {
  batch_id: string
  source_type: 'daily' | 'wrong_book' | 'manual'
  
  main_queue: ReviewItem[]      // 主队列：首次作答=normal_review
  retry_queue: ReviewItem[]     // 重试队列：纯前端逻辑
  
  stats: { total, completed, retry_count }
}

interface ReviewItem {
  schedule_id: string
  chunk_id: string
  chunk_title: string
  chunk_content: string
  position: number
}
6.2 主队列消费（首次作答 = normal_review）
async function consumeMainQueue() {
  while (batch.main_queue.length > 0) {
    const item = batch.main_queue.shift()!
    
    // 1. 展示卡片，用户首选
    const choice = await showReviewCard(item)  // 'mastered' | 'vague' | 'forgotten'
    
    // 2. 【关键】展示答案与解析（当前逻辑不变）
    await showAnswerAndExplanation(item)
    
    // 3. 解析后用户二次确认（或直接用首选，见下）
    //    这里简化：首选即最终，展示解析仅为学习
    //    若产品要求解析后再选，改为二次弹窗
    
    // 4. 调用后端正式复习接口
    const resp = await api.review.normal({
      schedule_id: item.schedule_id,
      chunk_id: item.chunk_id,
      answer: choice,
      response_time_ms: Date.now() - cardShowTime
    })
    
    // 5. 处理响应
    if (resp.need_session_retry) {
      // 模糊/遗忘 → 压入重试队列
      batch.retry_queue.push({ ...item, retry_reason: resp.retry_reason })
    } else {
      // 认识：卡片销毁
      batch.stats.completed++
    }
    batch.stats.completed++
    updateProgressUI()
  }
  
  if (batch.retry_queue.length > 0) await consumeRetryQueue()
  else await runPostSessionVerification()
}
6.3 重试队列消费（纯前端，无后端交互）
async function consumeRetryQueue() {
  while (batch.retry_queue.length > 0) {
    const item = batch.retry_queue.shift()!
    
    // 1. 展示卡片（带「🔁 重试」标记）
    const choice = await showReviewCard(item, { isRetry: true })
    
    // 2. 【关键】展示答案与解析（与主队列一致）
    await showAnswerAndExplanation(item)
    
    // 3. 解析后用户选择
    if (choice === 'mastered') {
      // 认识：本组放行，**不调用后端，DB 完全不变**
      batch.stats.completed++
      continue
    }
    
    // 不认识/模糊 → 压回队尾，无限循环
    // ⚠️ 纯前端，无接口、无日志、DB 完全不变
    batch.retry_queue.push(item)
    batch.stats.retry_count++
  }
  
  await runPostSessionVerification()
}
6.3 中途退出处理
情况	处理方式
已完成 normal_review	接口已调用，DB 状态已落库生效，保留
main_queue/retry_queue 未作答	全部退回全局待复习池，下次复习重新分组
当前展示的卡片	已作答按已作答处理；未作答按未作答处理
7. 完整卡片分支说明
分支 1：首次作答【认识】（normal_review）
前端调用正式作答接口 answer=mastered
后端执行完整 SM-2 正向逻辑：提升 ease_factor、correct_streak +1，拉长 next_review_time；满足毕业条件置 is_mastered=true
前端展示答案解析 → 卡片销毁，本组不再复现
分支 2：首次作答【模糊】（normal_review）
前端调用正式作答接口 answer=vague
后端小幅降级：降低 ease_factor，缩短 next_review_time，DB 落库
返回 need_session_retry: true，单词压入本组重试队列
前端展示答案解析 → 用户阅读后继续
本组内无限循环，直到选择【认识】才放行
分支 3：首次作答【不认识】（normal_review）
前端调用正式作答接口 answer=forgotten
后端执行完整降级逻辑：大幅降低 ease_factor，correct_streak=0，生成更近的 next_review_time 落库
返回 need_session_retry: true，单词压入本组重试队列
前端展示答案解析 → 用户阅读后继续
本组内无限循环，直到选择【认识】才放行
分支 4：重试队列阶段（session_retry，纯前端）
单词已完成一次正式作答，数据库状态固定不变

用户操作	前端行为	后端影响
再次选【不认识】/【模糊】	展示答案解析 → 压回重试队列尾部，循环弹出	无接口、无日志、DB 完全不变
再次选【认识】	展示答案解析 → 仅前端放行，退出重试队列	DB 所有记忆参数完全不变
业务结果：本组会话放行，但单词仍按首次正式作答生成的 next_review_time，未来回到全局待复习池参与正式复习。

8. 组后验证环节（独立于重试逻辑）
验证环节独立于 session 重试逻辑，错误会修改后端状态

收集对象：本组内发生过 normal_review = vague | forgotten 的知识点集合 verification_set
执行验证：费曼解释 / 概念辨析 / 代码补全 / 关键词填空
验证失败：调用后端 POST /api/review/verification-failed，独立分支：轻微下调 ease_factor，DB 落库
验证通过：仅完成校验，不修改全局记忆进度
9. 关键产品行为与风险点
9.1 复习债来源
全局待复习池不会自动清空
每日新增知识点设置过高，会持续累积到期任务
9.2 用户认知现象
现象：本组内「模糊/不认识」反复作答，本组答对放行，但过一段时间该知识点再次出现在全局待复习池

产品解释（需在 UI 明确提示）：

本组内答对属于会话即时回忆（工作记忆激活）
不能抵消正式复习「模糊/不认识」带来的数据库降级结果
必须在下一次正式全局复习答对，才算有效记忆进度推进
9.3 用户自主权
用户可随时中断复习，剩余任务保留在全局池子
支持手动「标记掌握」：直接置 is_mastered=true，移出待复习池；若在当前组内存队列，直接从内存移除
复习与学习新内容/生成测验互不阻塞，用户可自由切换

11. 异常与边界情况处理
11.1 用户行为异常
异常行为	检测方式	处理策略
极速点击 (< 500ms)	response_time < 500ms	标记无效作答，不计入统计，不改变队列状态，提示"请仔细思考后再作答"
长时间不操作 (> 5分钟)	前端定时器检测	自动暂停计时，保存进度到 Redis，提示"已暂停，点击继续"
频繁切换反馈	同一题目短时间多次提交	仅保留最后一次有效提交，前端按钮防抖 1 秒
恶意刷分/刷熟练度	统计异常模式检测	标记账号风险，限制复习频次，人工复核
11.2 系统异常
异常场景	降级方案	恢复机制
中途退出/杀进程	已作答落库，未作答退回全局池	再次进入自动恢复会话
网络断开	本地 localStorage 缓存操作	联网后自动回放，幂等去重
Redis 宕机	读取 DB 重建会话，降级单次遍历	Redis 恢复后自动同步
版本冲突(并发)	乐观锁失败返回当前状态	前端自动重试 1 次
11.3 业务边界
边界条件	处理方式
批次题目为 0	返回"暂无待复习内容"，引导去导入文档/做测验
单组题目 > 20	限制 max_items=20，超过自动分批
用户只想复习错题	source_type=wrong_book，仅从错题本选题
用户想指定标签复习	source_type=manual + tag_filter
知识点永久掌握	连续 3 次正式复习全 mastered → is_mastered=true，退出复习池
手动标熟	直接置 is_mastered=true，移出待复习池；若在当前组内存队列，直接移除

13. 附录：术语表
术语	定义
全局待复习池	数据库 review_schedule 表中 next_review_time <= now() 且 is_mastered=false 的记录集合
复习组	前端内存临时对象，包含 main_queue 和 retry_queue，单次会话 15-20 个知识点
主队列	复习组内原始待复习队列，首次作答走 normal_review
重试队列	复习组内会话错题队列，纯前端逻辑，走 session_retry
正式复习	调用后端 SM-2 接口，修改数据库状态
会话重试	仅前端内存运算，无后端交互，不修改 DB
放行	重试队列中选择【认识】，卡片销毁，不再复现
复习债	全局待复习池积压未完成的任务总量
组后验证	复习组核心结束后的独立验证环节（费曼/辨析/补全）
毕业/永久掌握	连续 3 次正式复习全 mastered → is_mastered=true，退出复习池
复习债清零	待复习池为 0 的状态
